# Plan 0.3.0

Status: plan, written 2026-10-27 on branch `feat/0.3.0`, based on `main` 32c12bb (= npm 0.2.1).

## Goal

0.3.0 repairs and refreshes the code generator (vendor Network API v11), closes the open items of `BACKLOG.md` and takes the three open Dependabot updates, without breaking any MCP gateway that pins 0.2.1.

## Consumer contract (hard limits for every step)

- No tool is renamed or removed; the tool count only grows.
- No new required param on an existing tool; no changed default; no input that 0.2.1 accepted is rejected (neither by the published JSON schema nor by the zod schema nor at call time before the request).
- Read tools keep their name prefixes.
- New environment variables are optional, default to the 0.2.1 behaviour, and are documented in `.env.example`, `server.json`, `mcpb/manifest.json` (where a user setting makes sense) and the README.
- `npm ci && npm run build` and `node dist/index.js` keep working on Node 22.12+; `prebuild` keeps gating the build.
- Every schema-visible change is listed in `CHANGELOG.md` 0.3.0 under "Behaviour changes for callers"; hard fields in `tests/contract/tools-contract.json` are edited by hand, description and schema-byte noise is accepted with `UPDATE_CONTRACT_NOISE=1`.
- No call to api.ui.com or a console. Fetching the public vendor documentation (developer.ui.com) is allowed for the codegen refresh only.

## Done criteria

1. `npm ci`, `npm run lint`, `npm run typecheck`, `npm run format:check`, `npm run test:unit`, `npm run build`, `npm run test:stdio`, `node scripts/smoke-stdio.mjs` green locally on Node 22.12.0 and the current Node (full suite once per change, per CLAUDE.md).
2. `tests/unit/contract.test.ts` green against the updated snapshot; the snapshot diff against 0.2.1 contains only added tools, added optional properties and the annotation change listed below, checked by `tests/unit/contractCompat.test.ts` against `tests/contract/tools-contract-0.2.1.json`, the full `tools/list` of 0.2.1 (inputSchema and annotations of every tool, dumped from 32c12bb and frozen): it fails on any removed tool, removed property, new required entry, changed default, changed param schema of a hand-written tool, added property that does not accept every value, or annotation change other than the listed ones. `tests/unit/generatedCompat.test.ts` checks the params of the generated tools against the same file.
3. Acceptance replay of 0.2.1 input: `tests/unit/contractCompat.test.ts` calls every tool that existed in 0.2.1 with a minimal valid call and again with an unknown extra key and a wrong-typed value for every added property, and asserts both are accepted (`unifi_net_block_client` and `unifi_net_unblock_client` refuse every call, as in 0.2.1) and send the same requests and the same confirm preview; `tests/unit/generatedCompat.test.ts` replays `body` as object, string, number, array and `null` against every generated write tool and asserts the preview carries the body unchanged; `tests/unit/bodyOptional.test.ts` covers `body` absent.
4. `npm run codegen -- --offline` reproduces `src/tools/generated/` byte for byte from the committed vendor specs (drift test in CI).
5. Version 0.3.0 in `package.json`, `package-lock.json`, `server.json` (top level and package), `mcpb/manifest.json`; CHANGELOG 0.3.0 "Unreleased"; 0.2.1 dated 2026-10-27.

## Decisions per backlog item

### Code generator and tool schemas

- **Codegen source (N-37, N-44, N-63, N-36, N-38): fix in 0.3.0.** The generator reads the vendor OpenAPI documents instead of scraping one RSC page per endpoint. Reasons: request bodies sit under `content["application/json"].schema` in standard OpenAPI (N-37), `$ref`s resolve against `components.schemas`, and one file per surface makes fixtures for all pages trivial (N-44). Design:
  - `npm run codegen` downloads `site-manager/v1.0.0/openapi.json` and `network/v11.0.97/openapi.json` into `tests/fixtures/openapi/`, then generates from those files; `npm run codegen -- --offline` generates from the committed files only. Generation writes into a temp directory and replaces `src/tools/generated/` only when every catalog entry succeeded (N-44); a missing operationId fails the run and leaves the old files.
  - The catalog maps each slug to an operationId (lowercase match) and stays the single list of generated tools; `gethost` and `getsdwanconfig` become `gethostbyid` and `getsdwanconfigbyid` (N-36): two NEW tools `unifi_gen_gethostbyid` and `unifi_gen_getsdwanconfigbyid`, 82 generated, 169 total. No existing tool is renamed. The `connector*` catch-alls stay out (covered by `unifi_raw_request`, which has the path checks).
  - Network pin `v10.3.58` -> `v11.0.97` (N-38). Descriptions of all generated tools change (doc path), reported as noise.
  - `tests/fixtures/rsc/` and `src/client/rsc.ts` go away once nothing reads them; `tests/unit/network.handlers.test.ts` takes its path templates from the OpenAPI fixture. `NOTICE` names `tests/fixtures/openapi/` instead (same status: vendor documentation, not MIT). Ruling: the RSC fixtures already embed the full spec (about 780 KB each), so committing the two OpenAPI files does not widen what the repository carries.
  - Drift check: `tests/unit/codegen.generated.test.ts` re-emits from the committed fixtures and compares byte for byte (runs in CI through `test:unit`). An online "newer vendor version" check in CI is dropped: CI must not depend on developer.ui.com; the maintainer runs `npm run codegen` when the vendor moves.
- **Typed bodies stay non-breaking (N-37, N-63).** Every generated `body` becomes `z.union([<typed schema>, z.unknown()]).optional()`:
  - The typed branch gives the model the vendor shape (JSON schema `anyOf: [<typed>, {}]`); the `z.unknown()` branch accepts everything 0.2.1 accepted, so neither zod nor a JSON-schema-validating gateway rejects old input.
  - Inside the typed branch, objects are loose (`z.looseObject`), so unknown keys are kept and sent as before, never stripped; a value that matches the typed branch is passed through unchanged (test: deep equality of the sent body for matching and non-matching input).
  - `body` stays optional even where `requestBody.required` is true; the description says "The API requires a body" instead (a required `body` would be a new required param).
  - N-63: a property the vendor marks required whose emitted schema is `z.unknown()` gets `.optional()` (keeps the zod 3 behaviour); in practice covered by the union fallback anyway.
  - Path and query params of existing tools keep their 0.2.1 schemas: a param whose type is a `$ref` keeps emitting `z.unknown()`, and `default` values from the spec are not emitted (they would change contract defaults). Test: for every tool in the 0.2.1 snapshot, required list, property names and defaults are equal, and param JSON schemas are equal except `description`.
- **N-26 fix in 0.3.0:** the confirm preview of generated write tools shows the query string (filter, force) as sent. Contract: none.
- **N-27 fix in part:** `unifi_gen_queryispmetrics` gets the annotations of its read-only twin `unifi_sm_query_isp_metrics` (`readOnlyHint: true, destructiveHint: false, idempotentHint: true`); `unifi_net_block_client` gets `idempotentHint: true` (blocking twice equals blocking once; the tool sends nothing today). Implemented as a codegen override list plus the hand tool. Contract: annotation change, by hand in the snapshot, listed for callers. Dropped part: creates keep `destructiveHint: true`, because lowering it would loosen approval rules of gateways and clients that key on that hint.
- **N-43 fix in 0.3.0:** the client stops sending `[object Object]`: a plain object query value is JSON-encoded, an array value is sent as repeated keys (`hostIds[]=a&hostIds[]=b`, as `unifi_gen_listdevices` needs; 0.2.1 sent `a,b`), strings, numbers and booleans as before. The `filter` schema of `unifi_gen_getdevicetagpage` stays `z.unknown()` (forcing `z.string()` would reject objects 0.2.1 accepted); its description points to the vendor string filter syntax. Not verifiable without a console: whether the API accepts a JSON-encoded filter is unproven, stated as such in the CHANGELOG.

### Hand-written tools

- **N-39 fix:** optional `offset`, `limit`, `filter` on `unifi_net_list_acl_rules`, `list_dns_policies`, `list_traffic_lists`, `list_vouchers`, `list_switch_stacks`, `list_mclag_domains`, `list_lags`, `list_sites`; optional `pageSize`, `nextToken` on `unifi_sm_list_hosts`, `unifi_sm_list_sites`, `unifi_sm_list_devices` (plus optional `hostIds` array and `time` there). Absent params send nothing, so the request equals 0.2.1. Contract: additive optional properties.
- **N-40 fix:** optional `duration` enum (`24h`, `7d`, `30d`) on `unifi_sm_get_isp_metrics`; the description says it cannot be combined with the timestamps (the vendor decides; no new local rejection of existing inputs).
- **N-45 fix:** table-driven method, path, query and body assertions for every `unifi_net_*` tool, written before the refactors below (N-47, N-65, N-66, N-86) so they hold them.
- **N-65 fix:** `unifi_net_port_action` spreads `body` first and the mapped `action` last. Behaviour change for callers: `body.action` no longer overrides `action` (listed).
- **N-66 fix:** one helper builds preview URLs, console id encoded like the request.
- **N-47 fix:** one shared request helper module for the hand tools (after N-45 so the tests pin behaviour).
- **N-86 fix:** one error-mapping helper; every tool returns `statusCode` and, where known, `code` in error details. Additive fields only.
- **N-48 fix:** remove the dead throw in `src/client/retry.ts` and `Discovery.reset()` if nothing uses it (verify with a search first).
- **N-35, N-64 fix:** pass the MCP request `signal` into `fetch`, abortable retry sleep, listener removed after each attempt; a caller abort is reported as `code: CANCELLED`, a timeout stays `TIMEOUT`.
- **N-41, N-79 fix:** prompt texts and the README line name only fields the API returns. `unifi-audit-firewall` keeps its optional `siteId` arg (removing it could reject callers that pass it); the text says the tools use the configured or discovered site.
- **N-42 fix:** discovery keeps preferring hosts of type `console`; only when none matches, an owned `ucore` host is used instead of failing. Today's successful setups pick the same console; only former discovery errors change. README and `UNIFI_CONSOLE_ID` docs say so.
- **N-80 fix:** a closed stdio transport is logged at `error` and the process exits with code 1. Behaviour change for callers (exit code), listed.
- **N-22 fix (opt-in):** new optional `UNIFI_REDACT_SECRETS` (default `false` = 0.2.1 output); when on, read results mask the same keys the confirm preview redacts.
- **N-23 fix (opt-in):** new optional `UNIFI_READ_ONLY` (default `false`); when on, every write tool stays registered but returns an error result without a request. New optional `dry_run` boolean on every write tool: `true` returns the preview and never executes, independent of `confirm`. Contract: additive optional property on all write tools.
- **N-32 fix (opt-in):** new optional `UNIFI_MAX_RESULT_BYTES` (default unset = no cap, as 0.2.1); when set, longer results are cut with a truncation marker that names the paging params. A default cap would change results 0.2.1 returned in full.
- **N-94 drop:** `MaxListenersExceededWarning` comes from the SDK stdio transport at about 30 parallel calls, is stderr noise only and belongs upstream; re-check after the SDK update in this branch and keep the item only if it still appears.
